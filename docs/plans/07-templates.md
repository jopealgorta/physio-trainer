# Templates (spec 07) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Routine and weekly-plan templates (no customer), saved from customer work or created from scratch, assigned to a customer as an independent deep copy.

**Architecture:** `routines`/`weekly_plans` gain `is_template` + `source_template_id`; a template is a row with `customer_id is null`. Copying lives in one pure id-map helper (`src/lib/templates.ts`) and two copy mutations (`copyRoutine`, `copyPlan`) used by assign, save-as-template and duplicate. Existing editors, lists and board are reused with a template mode; new UI lives in `src/components/templates/`.

**Tech Stack:** Next.js 16, Drizzle + Supabase Postgres (RLS), zod v4, next-intl, shadcn/ui, Vitest, Playwright.

**Spec:** `docs/specs/07-templates.md` (answers to open questions are recorded there). Also read `docs/architecture.md` and `docs/specs/05-routines.md`, `docs/specs/06-weekly-plans.md` ("Decisions made during implementation").

## Global Constraints

- Tenancy: every mutation takes `(tx, physioId, input)`, filters by `physio_id`, runs through `withPhysio` in actions. Copy actions verify template and target customer/case belong to the physio.
- Migrations are generated by drizzle-kit (`pnpm db:generate`); hand-written SQL only for what drizzle can't express (column-list `SET NULL` FK), in a separate migration. Expand-only: nothing dropped or renamed.
- i18n: every string in **both** `messages/en.json` and `messages/es.json` (Rioplatense voseo: "ingresá", "elegí"), namespace `Templates`; `src/i18n/messages.test.ts` must pass. Dates/numbers via next-intl formatters.
- Use shadcn primitives (`Select`, `Input`, `Label`, `Textarea`, `Dialog`...). Radix Select: `toSelectValue`/`fromSelectValue` (`src/lib/select-value.ts`), `onValueChange` ignores `""`, hidden `<input name>` for form fields; tests pick options with `chooseOption` (`src/test/select.ts`, `e2e/helpers/select.ts`).
- Server Actions are `async function` declarations (a `"use server"` file cannot export arrow constants). Don't pass functions/icons from Server to Client Components.
- Accent colour = `primary` token. No new top-level route (so `RESERVED_HANDLES` unchanged).
- Next.js 16: `params`/`searchParams` async; check `node_modules/next/dist/docs/` before using an unfamiliar API.
- Test-first. `pnpm check` before every commit; integration tests (`pnpm test:int`, needs `pnpm db:start`; run with node v24 via nvm) for server tasks.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- Template whose name is 80 chars: "(copy)"/assign names must be truncated to the 80 limit, not rejected.
- Plan with one routine on all 7 days: copy has one routine row referenced by all 7 entries (Task 3 int test).
- Assigning an **archived** template, an empty template as `active`, or to an **archived** customer: refused with a typed error (Task 3).
- Copy racing a save of the template: `copyRoutine`/`copyPlan` lock the source rows `for share` (saves take `for update`), so a copy never sees half-replaced items (Task 3, code comment + review).
- Templates must not leak into customer lists, pickers or another customer's attach list (Task 4 int test).
- Archiving a template routine used by an active template plan is blocked like customer routines (Task 4).

```ts
/** Copies header, groups, items, sets. Locks the source `for share` (saveRoutine locks `for update`). */

// duplicateRoutine keeps its signature; it now calls copyRoutine with
// (s) => ({ name: options.name, customerId: s.customerId, caseId: s.caseId, isStandalone: options.isStandalone,
//           status: options.status ?? s.status, isTemplate: s.isTemplate, sourceTemplateId: s.sourceTemplateId })

// plans/mutations.ts
export type PlanCopyTarget = {
  name: string; customerId: string | null; caseId: string | null; status: RoutineStatus;
  isTemplate: boolean; routineStatus: RoutineStatus;
  /** Record provenance: plan.source_template_id = source plan, each routine copy's = its source routine. */
  linkSource: boolean;
};
export function copyPlan(tx: Tx, physioId: string, sourceId: string, target: PlanCopyTarget):
  Promise<Result<{ id: string }, "notFound">>;
// Locks the plan `for share`, copies notes, entries (weekday/position/label), and each DISTINCT referenced
// routine once via copyRoutine (isStandalone false, customerId/caseId/isTemplate from target, status =
// target.routineStatus), then inserts entries through remapEntries(distinctRoutineIds(...) map).

// templates/schemas.ts  (zod + input types; names reuse ROUTINE_NAME_MAX / PLAN_NAME_MAX = 80 via a kind-aware helper)
createTemplateSchema  = { kind: "routine"|"plan", name }
saveAsTemplateSchema  = { kind, sourceId: uuid, name }
assignTemplateSchema  = { kind, templateId: uuid, customerId: uuid, caseId: uuid|null (blank → null), name, status: "draft"|"active" }
duplicateTemplateSchema = { kind, templateId: uuid, name }
export type TemplateError =
  | "notFound" | "alreadyTemplate" | "templateNotFound" | "templateArchived" | "customerNotFound"
  | "customerArchived" | "caseNotFound" | "needsItems" | "needsEntries";

// templates/mutations.ts — all return Result<{ id: string }, TemplateError>
createTemplate(tx, physioId, { kind, name })                       // empty, status "active", routine isStandalone true
saveAsTemplate(tx, physioId, { kind, sourceId, name })             // source must be non-template, else "alreadyTemplate"; status "active"; notes copied verbatim; no source link; routine isStandalone true; plan copy routines status "active"
assignTemplate(tx, physioId, { kind, templateId, customerId, caseId, name, status })
duplicateTemplate(tx, physioId, { kind, templateId, name })        // template→template: copy keeps the source's status; no source link
```

Standalone routine copy: `isStandalone: true`. For a plan, copied routines are `isStandalone: false`.
